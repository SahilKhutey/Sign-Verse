# Contributing to SignVerse

We love your input! We want to make contributing to SignVerse as easy and transparent as possible.

## Development Process

1. Fork the repo and create your branch from `main`
2. Make your changes
3. Add tests and ensure they pass
4. Update documentation
5. Submit a pull request

## Code Style

### Python
- Follow PEP 8 guidelines
- Use type hints
- Document functions with docstrings
- Maximum line length: 88 characters

### JavaScript/TypeScript
- Use ESLint and Prettier
- TypeScript for all new code
- Functional components with hooks

### Commit Messages
- Use conventional commit format
- Example: `feat: add new pose estimation model`

## Pull Request Process

1. Update `CHANGELOG.md` with your changes
2. Ensure all tests pass
3. Get approval from at least one maintainer
4. Merge using "Squash and merge"

## Adding New Features

1. Create a feature proposal issue first
2. Implement the feature with tests
3. Update relevant documentation
4. Add examples if applicable

## Bug Reports

Please use the issue template and include:
- Steps to reproduce
- Expected behavior
- Actual behavior
- Environment details

## Feature Requests

We welcome feature ideas! Please include:
- Use case description
- Proposed implementation
- Alternatives considered
